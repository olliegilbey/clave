# FOOTGUNS.md

Traps that already cost someone a round. Things that compile, parse, read or
look fine — and are wrong anyway.

**Grep this file the moment something behaves unexpectedly, before you start
debugging.** Entries are written so the words you would search for — an error
string, a symbol, a command — come first.

Tags:

- untagged — a live trap. It will bite you today.
- **[FIXED]** — it bit someone, it is now guarded. Do not reintroduce it; the
  entry records why the guard exists.
- **[DESIGN]** — a locked design decision not yet implemented. The trap is in
  building against the old assumption.

Add to this file whenever you lose time to something the next agent would also
lose time to. One line, mechanism first, cite the source.

## Zellij behaviour

Zellij's own source is the authority. Vendored at
`~/.cargo/registry/src/*/zellij-tile-0.44.3/` and `…/zellij-utils-0.44.3/`.
Note `zellij-server` is **not** vendored — claims about it trace to
[SUBSYSTEM-VALIDATION.md](docs/superpowers/spikes/SUBSYSTEM-VALIDATION.md),
which is a ledger of things observed live.

- **Plugin identity is `(location, configuration)` compared exactly — a miss STARTS A NEW PLUGIN rather than no-oping.** `impl PartialEq for RunPlugin` compares exactly `(&self.location, &self.configuration)` and `RunPlugin` derives `Hash` (`zellij-utils/src/input/layout.rs:518-526`, `:424-425`). A pipe or reload whose config does not match logs `"Plugin {} not found, starting it instead"` and spawns a second bar. This is the mechanism behind the v0.1.1 double-sidebar (#43/#44). Grep string when it happens: `not found, starting it instead`.
- **`PluginUserConfiguration::new` silently strips 14 reserved keys** — `hold_on_close`, `hold_on_start`, `cwd`, `name`, `direction`, `floating`, `move_to_focused_tab`, `launch_new`, `payload`, `skip_cache`, `title`, `in_place`, `skip_plugin_cache` (`zellij-utils/src/input/layout.rs:532-548`). A config key with one of those names is invisible to plugin identity, so it can never disambiguate two instances. Check this before adding a config key to fix a skew problem.
- **`Event::TabUpdate` reaches only the ACTIVE tab's plugin instance** — hidden instances are event-starved: stale active flags, stale tab sets (a new tab is invisible to them), no observable transition. `PaneUpdate` likewise. Only pipes and store-snapshot pushes broadcast. (SUBSYSTEM-VALIDATION C3)
- **`is_active_instance()` is NOT a visibility gate** — every hidden instance's stale tab set claims its own tab is active, so anything gated on self-diagnosed "am I active" is poisoned during event bursts. Cost three rounds ending in an `EMFILE` server crash. The only trustworthy signal is the executor gate (own tab == replicated beacon). (C6 rounds 11–13)
- **`render()` is not visibility-gated either** — every instance renders at least once after load, so "hidden panes never render" holds only in steady state. A render-driven announce crashed the server with EMFILE on the first Alt+c (252 announces, 460 events in one second). (C6 round 13)
- **`resize_pane_with_id` silently refuses fixed-size panes — `CantResizeFixedPanes`.** It flashes "FIXED!" on the pane; the plugin sees nothing. Layout sizes must be percentages (`size="15%"`), in all three generators. (C6/C8)
- **zellij emits NO events for plugin-initiated resizes** — the only feedback is the plugin's own `render()`. Cross-tab width healing is structurally blind. This killed the entire repair-by-command architecture. (C6 rounds 10, 18)
- **`show_self()` is a focus action** — the server maps it to `Action::FocusPluginPaneWithId`, which switches to that pane's tab; ten hidden instances calling it is ten racing focus actions. Use `show_pane_with_id(PaneId::Plugin(own), false, false)` → `UnsuppressOrExpandPane`. (C6 round 14)
- **`suppress_pane` damages the tab's swap state, so `swap_tiled_layout` can never restore an unsuppressed pane** — `suppress_pane` → `extract_pane` → `set_is_tiled_damaged()`, and `add_tiled_pane` auto-relayouts only when NOT damaged. Other damage-setters: `resize_pane_with_id`, `resize_whole_tab`, close/extract/splits. The swap layout parsed perfectly and never fired. (C6 round 19)
- **zellij RECYCLES tab ids** — `get_new_tab_id` is `self.tabs.keys().last() + 1` over a `BTreeMap` (`zellij-server/src/screen.rs:1617`), so closing the *highest*-id tab hands that id to the next tab created. Makes bind/timeline pruning correctness-critical, not hygiene.
- **`children` must be a DIRECT child of `default_tab_template`.** Nesting it inside a wrapper pane *parses fine*, but the fill path `default_template()` inserts the default terminal pane only at the template's own top-level `external_children_index` and does not recurse (`zellij-utils/src/kdl/kdl_layout_parser.rs:1747-1761`, non-recursion enforced at `:1712`). Result: tabs with a bar and **no terminal**. Symptom in a dump: the wrapper keeps `external_children_index=Some(n)` forever.
- **`default_tab_template` wraps EXPLICIT `tab` nodes too** — so a `tab` node carrying its own bar pane renders TWO plugin instances in one tab: visibly wider, executor election scrambled, presenting as a dead Alt+c. Launch layouts must use a bare tab node and let the template's `children` slot take the terminal. (commit `5cb8b17`)
- **Layout sibling panes stack HORIZONTALLY (rows) by default** — `impl Default for SplitDirection = Horizontal` (`layout.rs:2065-2069`), and under Horizontal `size=N` binds to *rows* while cols is inherited (`:1947-1955`). `pane size=26` gives a 26-ROW top strip, not a left column. Fix: `split_direction="vertical"` on the parent.
- **Mixing bare top-level `pane` nodes with `tab` nodes is a parse error: `"Cannot have both tabs and panes in the same node"`** (`kdl_layout_parser.rs:2269/:2286/:2316`). `default_tab_template` plus bare top-level panes is fine.
- **A `MessagePlugin` block inside a `bind` needs a node terminator after its closing `}` — a newline or a `;`.** The multi-line form parses fine without one; the inline form `bind "Alt h" { MessagePlugin "…" { … } }` fails with `Expected valid node terminator.` (kdl 4.7.1). Zellij's own corpus writes `};`, which is why the `;` habit stuck. It fails at *session launch* — catch it with `zellij --config <cfg> setup --check`.
- **Zellij plugin permissions are ALL-OR-NOTHING per plugin** — a partial cache match raises an interactive prompt that is effectively unanswerable in a narrow bar pane, and withholds the *entire* set, so every `zellij pipe` times out with `Action CliPipe did not complete within 1s` and nothing renders. Pre-seed `permissions.kdl` under BOTH the `"file:<abs>.wasm"` and `"<abs>.wasm"` key forms. Read the current file rather than any doc for the exact set. (format: `zellij-utils/src/kdl/mod.rs:5456-5500`)
- **`EventType::InputReceived` carries no payload** — `EventType` is a strum discriminant enum over `Event` (`zellij-utils/src/data.rs:943`), so *every* variant is payload-free by construction. It cannot distinguish a nav keybind from a keystroke. Using it spawned one subprocess per keystroke and exhausted the server's file descriptors. EMFILE panic site: `zellij-utils/src/ipc.rs:388`, `try_clone_stream().unwrap()`.
- **`zellij action` against an absent or dead session blocks INDEFINITELY and never errors** — an ungated `dump-layout` once hung `dev status` for minutes. Always gate on liveness first.
- **`go_to_tab(position+1)` is a silent no-op from a plugin** — a 0-/1-based mismatch, not a client-context problem (ruled out by driving it from a keybind). Use `focus_pane_with_id(PaneId::Terminal(id), false, false)`; zellij pulls the tab forward.
- **zellij live-watches `config.kdl` and hot-swaps keybinds into RUNNING sessions** (~1 s poll) — but the running bar keeps its load-time `initial_userspace_configuration`. So regenerating config against a live session re-keys its keybinds to an identity the on-screen bar does not have, and the next keypress starts a second bar. **Kill and relaunch every affected session after any `just release`, `clave setup`, or `clave dev scenario` that changes `clave_binary` or the wasm path.**
- **zellij resizes in ~5%-of-viewport steps** — "shrink while cols > 26" blew straight through the target (27→13). The seek is render-driven with an in-flight guard, a learned step clamped to `MAX_LEARNABLE_STEP = 20` (`clave-bar/src/model.rs:151`), and half-step acceptance. (C6 rounds 9, 16, 17, 20)
- **zellij's minimum-pane-width floor stops the collapse seek, and where it stops is window-dependent** — 14 cols on the dev window vs ~10 in the real session. "Wherever cols stop changing is accepted" is the ruling. (C8)
- **`move_pane_with_pane_id_in_direction` is a geometry SWAP** — the landing move hands the shrunk width to the terminal, so a width-then-move ordering races and pumps 75→30→75 on the fastest render chain. (C6 round 18)
- **zellij serializes the LIVE discovered pane process, not the baked layout command** — with MCP servers configured, `dump-layout` showed agent panes as `uv … run main.py`; an unreaped child once made every agent pane serialize as `command="<defunct>"`. Derive liveness from store binds, never from serialized command strings. (#6)
- **Every `zellij pipe` also delivers one empty EOF message per instance**, and logs `CliPipe did not complete within 1s timeout` plus `1000 consecutive unknown messages … logging client out` even with `unblock_cli_pipe_input`. Benign and pre-existing since v0.1.0 (#45) — but it buried the real evidence during the v0.1.1 incident. The keybind `MessagePlugin` path is clean.
- **`zellij --session <name> --layout <f>` means "add tabs to the EXISTING session"** and errors if absent. A new named session from a layout is `zellij -s <name> -n <layout>` (`zellij-utils/src/cli.rs:56-71`).
- **`CommandChanged` is a 1 Hz argv-change-gated sampler, and `is_foreground` means "the pane's direct child has a child"** — so its `true` transition is exactly command-*start* and never command-completion. Sub-second commands fall inside one poll window.
- **`Ctrl+D` in an agent pane does NOT close the tab** — panes run `clave spawn` (idempotent resurrect), so zellij holds the pane and re-runs it. `Alt+w` is the close path. (Note: `clave-bar/src/model.rs:1484` still has a stale comment claiming otherwise; the test is valid, its premise sentence is not.)
- **The zellij log is shared by EVERY session on the machine and old entries linger** — `$TMPDIR/zellij-<uid>/zellij-log/zellij.log` (macOS: under the OS temp dir, **not** `~/Library/Caches`, which holds `permissions.kdl` instead). A date filter is not enough: on a same-day cut it returns the previous version's loads too. Mark the line count before launching and read only what was appended.

## PATH and version coherence

The family of bugs that shipped v0.1.1 broken. See CONTRIBUTING "The one leak".

- **[FIXED] `clave-bar` used to shell out to bare `clave` through `PATH`** in 7 places while `config.kdl` baked the versioned path for keybinds only — so on 2026-07-22 a stale `0.1.0` binary served `clave open` inside a `v0.1.1` session and composed layouts pointing at the *old* wasm: two plugin populations, duplicate sidebar, dead nav. The CLI now arrives as the `clave_binary` plugin-config key (`clave-bar/src/plugin_config.rs:21`, `main.rs:371`), guarded by a literal-count test. **Do not reintroduce a PATH lookup.** (#43/#44, fixed in #66)
- **`just dev-install` rebuilds the SANDBOX wasm in place, so it is unsafe against a live `clave-test` session** — that is the remaining hazard, and it is the reason `just sandbox` (which refuses while `clave-test` is alive) is the reviewed path. It no longer touches the daily binary: since #43b it installs `~/.cargo/bin/clave-dev`, and since #43a the release owns an unversioned launcher at `~/.local/share/clave/bin/clave`. **[FIXED]** Before #43b it wrote `~/.cargo/bin/clave` — the name the daily surface answers to — which is how a working-tree build could take over the fleet. Do not reintroduce that name. If a pre-#43b `~/.cargo/bin/clave` survives on a machine it shadows the launcher: identify it (`command -v clave; clave --version`) before removing it.
- **`just dev-install` leaves the sandbox's `config.kdl` STALE** — it installs the wasm and CLI but never regenerates the sandbox config; only `dev scenario` calls `run_setup`. So `dev-install` then `dev launch` pairs a new `launch.kdl` with an old `config.kdl`, every keybind misses, and a second bar spawns — indistinguishable from "the fix didn't work". It produced a false negative during #44's own live validation. **`just sandbox` is the only path that yields a coherent sandbox.** (#31, open)
- **`launch.kdl` is stale by design until a cold start, so never assert on it *before* a launch.** Only `launch_session` writes it (`setup.rs:718`); neither `just release` nor `clave dev scenario` does. Any pre-launch check that includes it fails closed on a healthy setup — this has bitten twice: the release runbook's version glob, and `sandbox-setup.sh`'s #44 identity check, which read a pre-#44 `launch.kdl` from six days earlier and refused to set up a perfectly good sandbox. Check the freshly generated pair (`config.kdl` ↔ `layout.kdl`) before launch; assert `launch.kdl` after.
- **`just release` never rewrites `launch.kdl`** — `write_generated` writes `config.kdl` and `layout.kdl` only (`setup.rs:414-416`); `clave` composes `launch.kdl` at cold start. A `*.kdl` glob in a coherence check therefore orders a STOP on every healthy upgrade.
- **A version count is blind to UNVERSIONED references** — a KDL holding one correct versioned path *plus* a bare `clave` still reports "exactly one version" and passes, while the bare reference loads a second independent singleton. Probe the three sites explicitly: `clave_binary "clave"`, `Run "clave"`, `file:…clave-bar.wasm`.
- **Relaunching the old binary is NOT a rollback** — `clave` *attaches* to a live session (`setup.rs:733` `zellij attach --create`), so nothing is re-read; and once that session is dead, `config.kdl` still names the failed version, because `needs_version_refresh` (`setup.rs:589-595`) returns false as soon as the old binary's own wasm exists. Regenerate explicitly: `clave-v<LAST-GOOD> setup`.
- **`clave doctor` cannot see `PATH`** — its skew check compares only its own version against installed artifacts (`doctor.rs:326-352`). It reports "no issues" during exactly the incident the release runbook is hunting. (#48, open)
- **`runtime_binary()` probes only for its OWN version's copy** and falls back to bare `clave` (`release.rs:96-105`), which diverges from `config.kdl`'s versioned path. No longer silent: `binary_resolution_is_anomalous` (`release.rs:79-91`) warns and names the repair.
- **[FIXED] `starts_with("clave-v")` also matches a foreign `clave-vault`/`clave-verify`** in `bin/`, firing the divergence warning with no real mismatch — and a warning that cries wolf trains the reader to ignore the one that matters. Both sites now require a digit after `clave-v` (`setup.rs:270`, `release.rs:88`).
- **`zellij action start-or-reload-plugin` without `-c clave_binary=…` does not reload — it starts a second bar.** The one live mutation an agent may perform would spawn the very bug it exists to verify, while appearing to succeed.
- **Diagnosis is one grep:** `grep 'clave-bar: loaded' "$TMPDIR"/zellij-*/zellij-log/zellij.log`. Every line must report the same version **and the same `build=` tag** — the tag distinguishes two builds of the same version (`release.rs:44-50`, `clave-bar/src/main.rs:362`). `build=dev` means an untagged local build.
- **A shared `~/.cargo/bin/clave` is a multi-agent coordination hazard** — two agents `cargo install`ing from different worktrees silently swap the binary under each other. It has happened. (#31)

## Build, test, CI

- **A bare `cargo test` exits 0 while silently skipping every `clave-bar` test.** `default-members` excludes the wasm-only crate. Measured on this tree: `cargo test` = 140 passed, `cargo test --workspace` = 208 — **68 tests skipped, exit 0 either way**. `--workspace` is load-bearing on `test` *and* `clippy`.
- **`cargo fmt --all --check` is a CI gate and runs BEFORE clippy** — hand-edited Rust can be clippy-clean and still fail the build. `just gates` runs all four in CI's order. **But `lint` is not a required status check** — branch protection requires only `["test","wasm-build"]`, so a red fmt/clippy does not block a merge. (#68, open)
- **`crates/clave-bar` sets `[[bin]] test = false`** — tests placed in `main.rs` compile and then *silently never execute*. `main.rs` is ~598 lines containing **zero** `#[test]`; all clave-bar tests live in `model.rs`/`plugin_config.rs`, reached via `[lib]`. Anything in `main.rs` — all effect dispatch and event adaptation — is unreachable by any test.
- **[FIXED] clap-derive turns a bare `bool` positional into a FLAG (`SetTrue`)** — `clave collapse true` could never parse, and clap's own diagnostic `debug_assert` fires *only in debug builds*. Fixed with `#[arg(action = clap::ArgAction::Set)]` (`clave/src/main.rs:144`) plus a parse pin. Every new CLI surface needs one.
- **`debug_assert!` is compiled out of `--release`** — the only build a release cut ever uses. An assertion written that way asserts nothing where it matters. Use `anyhow::ensure!`.
- **A KDL string that *contains* the right substrings can still be structurally invalid**, and it fails at *session launch* — the worst place, because a dead `attach` blocks forever and the human sees nothing. `crates/clave/tests/kdl_guardrail.rs` parses every generated artifact with the real parser, pinned `zellij-utils = "=0.44.3"`, `kdl = "=4.7.1"`.
- **`keybinds.0` is a `HashMap`, so comparing every layout config against an arbitrary `kb[0]` is order-unstable** — an extra key on one keybind broke plugin identity just as fatally as a missing one, but a `kb[0]`-only comparison escaped **9 times in 40 runs**. Assert all entries agree with each other *before* using one as the value.
- **A source-text guard asserting the ABSENCE of a literal is near-theatre** — asserting `"clave",` is absent survived three live mutations (a byte-exact revert, variable indirection, and disabling the feature outright), all passing the full gate set. **COUNT the literal instead** (`clave-bar/src/plugin_config.rs:90`).
- **`cargo … | tail` reports tail's exit status, not cargo's** — a failed gate recorded as a pass. Set `pipefail`.
- **[FIXED] A cargo-dist *fragment* under `.github/workflows/` gets executed by GitHub** — `build-wasm-setup.yml` failed on every push, normalising red CI. Moved to `.github/` by #67. **cargo-dist regenerates it, so re-check the path after every dist upgrade.**
- **A blanket untracked-file exemption in the release gate is unsound** — tracked code can reference an untracked file (`mod foo;` with `foo.rs` never added): it builds locally but the tagged HEAD cannot reproduce it. Allowlisted to `docs/`, `.claude/`, `AGENTS.md` (`release.rs:161`).
- **[DISCHARGED, and it recurs] A mechanical search-and-replace of a width constant silently breaks a test.** When `BAR_TARGET_COLS` went 30 → 44 and `COLLAPSED_TARGET_COLS` 4 → 30, **sixteen** seek tests went red, and **two** were found to have stayed green while asserting nothing — `30` had been both the old target and an arbitrary "far from target" start width, and it is now the *collapsed* target, so a width that used to prove a shrink now proves a settle. **That sweep was not exhaustive**: a later review found a third shape it had missed. Three shapes to look for, all live: a start width that is now ON a target (converges in zero steps, asserts nothing); a landing whose delta no longer brackets the target (`seek_waits_for_inflight_resizes_and_zellijs_floor`'s floor loop turns from a near-target wall into a clobber re-drive); and — the one the sweep missed — a test that stays green and stays *meaningful* while quietly covering **less** (`harness_newborn_converges_on_the_template_from_above` started at 60 and drove two resizes against 30, but only one against 44, so it stopped exercising the post-learning band; nothing flagged it, and the fix was to pick a start width that still forces two). **Re-derive every width from the new targets; do not substitute numbers until the suite goes quiet — and check the tests that stayed green for lost coverage, not just for vacuity.** (#63)
- **`cargo add <crate>` respects a hand-written version cap already in `Cargo.toml`** — `cargo add dirs` left it at v5; needed `cargo add dirs@6`.
- **CodeRabbit reports `pass` while rate-limited** — "Review rate limited" appears in the check *detail*, not the colour; draft PRs report `Review skipped` the same way. A green CodeRabbit may have reviewed nothing. Read the detail. (#68, open)
- **`git branch --merged` lies under squash-merge** — a squash creates a new commit, so a merged branch's tip is never an ancestor of `main` and every merged branch reports unmerged. Verify with `gh pr list --state merged --json headRefName`.

## The bar's model — frame joins, latches, ordering

Read this section before touching `clave-bar/src/model.rs`. Every entry here is
a live defect or a live constraint, and S0–S8 all land in this file.

- **`is_active_instance()` and `own_tab_id()` join two independently delivered zellij frames BY TAB POSITION** — the last `PaneUpdate`'s `plugin_panes` against the last `TabUpdate`'s `last_tabs` (`clave-bar/src/main.rs:54-83`). A tab close renumbers positions, so in the window between the two frames the join silently returns a **different tab's** identity: the wrong bar elects itself, binds its agent to someone else's tab, and `apply_bind` evicts the rightful tenant (`store.rs:227-249`, "Evict any OTHER agent still bound to this tab_id"). Two separately reported symptoms are this one defect. (S0/#55)
- **`sent_binds` is a permanent latch** — inserted at emit, never removed, never cleared, not reset by `apply_snapshot` (`model.rs:197`, `:305`, `:429`, `:431`). So a wrong bind can never be corrected for the life of the plugin instance.
- **`birth_touched` latches on the tab ID, and zellij recycles ids** — close the highest-id tab, press `Alt+t`, and the new tab is *permanently* unstamped → sort key falls to `unwrap_or(0)` → below every dormant row (`model.rs:186-190`, `:384`, `:393`). Deterministic; no race required, so it likely fires more often than the races do.
- **`fire_binds()` is called after TabUpdate, PaneUpdate, `clave-status` and `clave-register` — but NOT after the hydrate snapshot** (`clave-bar/src/main.rs:424-441`, the `Event::RunCommandResult` arm), which is the only thing that populates `self.agents` at session birth. So the eager cold-start tab is frequently never bound at all, and `bind_effects` loops empty `agents` for zero iterations, silently.
- **A full-live-set prune payload is order-unsafe across processes** — two fire-and-forget `clave prune-tabs` subprocesses have no arrival order, so a "retain only these live ids" payload landing after a new tab's bind unbinds a **live** agent, and the `sent_binds` latch means it never re-fires. The payload carries observed-**stale** ids instead: idempotent and commuting (`model.rs:665-712`).
- **Prune emission must NOT be set-change-gated** — a close `TabUpdate` arriving before its `PaneUpdate` leaves `is_active_instance()` false, silently dropping the effect, and a set-change gate then never retries. Emission is detection-driven, self-limiting via the store echo; `last_live_ids` was deleted (`model.rs:675-694`).
- **`seek_last_cols` measured against a mid-flight *emit* anchor instead of the accepted rest width parks the bar off-target** — reproduced exactly as 30→16→6, then an external 26. `settle_at()` is the single settle helper and must pin the anchor at every settle path (`model.rs:978-992`). Pure logic inside a covered tier: the sim harness existed, the proptest never generated that interrupt shape. (#4/PR #27)
- **Two rapid `clave collapse` writes have no arrival order** — the change-gate swallows the correct write and the store pushes stale truth, *stickily*. Guarded by a pending-write ledger, `pending_collapse` + `collapse_reasserted` (`model.rs:266-273`, `:549-559`).
- **`now_unix()` stamps whole seconds and ties resolve on `tab.position` ascending** — two prompts 300 ms apart inside one wall second give the lower-positioned tab the win regardless of who was actually touched last (`store.rs:352-357`; sort at `model.rs:791`). The ordering key silently swallows a prompt.

## Claude transcripts — what the jsonl actually contains

The transcript tree is `~/.claude/projects/<munged-cwd>/<uuid>.jsonl`. Read it,
do not assume it: its line types changed under us once already.

- **`{"type":"summary"}` is EXTINCT — the label tier that has never once fired.** `summary_from_tail` (`hook.rs:116`) scans for it; Claude Code no longer writes it. Measured 2026-07-28: **0 of 919** local transcripts contain one, and all 14 live store rows read `label_source: first_prompt`, so every label is a truncated first-prompt fragment. Any test asserting `Summary`-tier behaviour is asserting against a hand-written fixture, not reality — re-point those at `ai-title`, do not delete them. Detect: `grep -rl '"type":"summary"' --include='*.jsonl' ~/.claude/projects | wc -l`. (#79)
- **The signals that DO exist:** `custom-title` (the user's rename), **`ai-title`** (Claude's rolling auto-description — the real replacement for `summary`), `last-prompt`, `worktree-state` (carries `worktreePath`, `worktreeName`, `worktreeBranch` — provenance with no git call), `relocated`, `agent-name`. Inventory them before designing a tier: `grep -ho '"type":"[a-z-]*"' ~/.claude/projects/*/*.jsonl | sort | uniq -c | sort -rn`.
- **A transcript RELOCATES when the session's cwd changes.** Claude moves the whole `.jsonl` into a project directory keyed on the NEW cwd, carrying its full history, and logs a `relocated` line. So any cwd frozen as a "stable transcript anchor" goes stale and the tail read silently stops returning anything — no error, just a row that never updates again. **S4 §3.2 asserts the opposite (*"never moves it"*) and is wrong.** Use `payload.transcript_path`, which every hook event carries. Verify: `find ~/.claude/projects -name '<uuid>.jsonl'` returns one hit, under the *current* cwd. (#59, #69)

## Rust and codebase specifics

- **`kdl` 4.7.1's `KdlDocument::get` returns the FIRST match only** (`kdl-4.7.1/src/document.rs:80`) — so a second `unbind` node in the generated config is silently ignored. All five unbound keys must ride one node, pinned by a `count == 1` test (`setup.rs:145-149`, `:948-966`).
- **The store lock must be a SEPARATE lockfile, never the data file** — the atomic rename swaps the data file's inode out from under a second writer's lock, and concurrent hooks silently lose updates. `agents.lock` is never renamed, so its inode is a stable anchor (`store.rs:2-9`, `:115`, `:147-148`).
- **`munge_cwd` must be fed the CANONICAL cwd** — Claude munges the physical `getcwd()` (macOS `/var`→`/private/var`, `/tmp`→`/private/tmp`), so callers must canonicalize *before* munging or the join key misses the jsonl and `clave spawn` hits `Session ID … is already in use` (`munge.rs:7-14`, enforced at `main.rs:219-221`).
- **[FIXED] `claude --session-id <uuid>` CREATES a session and refuses reuse against an existing jsonl** — which broke deterministic scenario seeding permanently after its first success. Now resume-or-create: an existing jsonl is the goal state, not an error (`dev.rs:208` `seed_needed`). Do not reintroduce unconditional seeding.
- **Backslash is KDL's escape introducer, and it passed every early guard** — a raw `\` in a baked cwd or a label (a prompt like `fix the \d regex`) is a layout parse error that can brick cold start through `launch.kdl`. `sanitize_label` filters `"` and `\` (`add.rs:80-93`); `validate_cwd` *rejects* rather than munges (`add.rs:152-159`), because a mangled path points nowhere and `clave spawn` would then canonicalize-fail on the lie.
- **`git rev-parse --show-toplevel` inside a LINKED worktree returns the worktree's own root** — inverting every `(wt)` marker and missing every store row keyed by the real root. Take the main tree from `git worktree list` entry 0 (`main_worktree_path`, `add.rs:211-213`).
- **Re-recording a resumed agent must NOT clobber its store row** — the row's `cwd` was canonicalized at creation and is worktree-aware; replacing it with the picked dir silently relocates a worktree agent to the repo root, bakes the wrong `--cwd`, and makes `clave spawn` miss the worktree-keyed jsonl and CREATE a fresh session. `merge_resume_record` resets only `status`/`tab_id` (`add.rs:335-360`).
- **`tab_position_of_pane()` must filter `!p.is_plugin`** — terminal and plugin pane-id spaces are different, so a plugin pane can shadow a terminal id (`clave-bar/src/model.rs:396-401`; `PaneMeta.is_plugin` populated at `main.rs:489-496`).
- **`register_plugin!` supplies its own `main` on zellij-tile 0.44** — adding an explicit `fn main()` to `clave-bar` is `E0428` (`clave-bar/src/main.rs:50`, `:597-598`).
- **`DefaultHasher` is not stable across toolchains** — anything hash-derived and user-visible (repo colours) would reshuffle on a `rustc` upgrade. Use store-backed iterate-and-wrap allocation instead. Standing constraint, currently unviolated.
- **Harness-injected text reaches `UserPromptSubmit` and would earn a permanent label** — resuming a session that died with pending background work makes the harness auto-fire a turn whose "prompt" is an orphaned tag. Earned labels stick, with no self-heal, so one leak bakes it forever. The guard matches the START of the trimmed string against `HARNESS_INJECTED_PREFIXES` and deliberately **never strips-and-uses the remainder** (`hook.rs:71-95`). (#17)
- **`CLAVE_*_BIN` overrides are deliberately NOT existence-checked** — a broken override must fail loudly at exec rather than be silently ignored. Do not "fix" this (`discover.rs:64-72`).
- **Use `which::which_global`, not `which`** — plain `which` lets the *cwd* satisfy a probe. A readable-but-not-executable file is not a hit either (`discover.rs:162-174`).
- **An OLDER `clave` binary writing the store SILENTLY STRIPS fields it does not know.** `with_store_mut` is read-modify-**write**: serde drops unknown keys on deserialize, so the whole row is re-serialized without them. Harmless for `title`/`summary` today — the #69 backfill re-seeds them from `label` at the next session create — but the moment S4 (#59) writes an *earned* summary from `ai-title`, a single old-binary write in a mixed-version window destroys it with no self-heal and no error. Any field holding earned state needs either a version guard or a re-derivation path. (#69 whole-branch review, #59)
- **[FIXED] `clave dev reset` must wipe only `["state", "repos"]`, never the sandbox root** — the old `remove_dir_all(root)` deleted `data/clave-bar.wasm`, a build artifact rather than scenario state, silently breaking the reset → scenario → launch loop with a rebuild demand. Test-pinned (`dev.rs:317`, `:418-424`).
- **[FIXED] Scenario worktree branches must NOT be tagged from the FRONT of `scenario_uuid`** — `add.rs:655`'s `&uuid[..8]` is fine on a real v4 uuid (effectively-random first 8 chars), but every `scenario_uuid` starts with the literal `00000000-`, so slicing the front 8 chars gives every scenario agent the SAME tag. Invisible until a scenario put two worktree agents in one repo (`ux-gate1`): `git worktree add -b clave/00000000` collided on the second one and failed closed. Tag from the TAIL instead (`dev.rs`'s `uuid_tag`, which is exactly the `{n:08}` suffix `scenario_uuid` mints) — any new scenario sharing a repo across 2+ worktree agents relies on this.

## Text, glyphs, rendering

- **Write every glyph as a `\u{...}` escape in source, never as a literal character.** Literal glyphs were silently lost in transit twice in one session; the first loss was misread as missing font coverage and nearly constrained the whole design to one Unicode plane. The failure mode is tofu in production from a diff that looked clean. **BARELY APPLIED — only `LABEL_SEP` (`clave-types/src/lib.rs`) and the tests written alongside it use the escape form; the 24 rendered sites are still literals**, including `Status::glyph` (`clave-types/src/lib.rs:37-41`), the stale/opening/dormant glyphs (`clave-bar/src/model.rs:771-775`), the truncation `…` (`clave-bar/src/main.rs:583`), and the label separator `·` (`add.rs:313,716`, `hook.rs:170,179,195`). Test assertions duplicate the same literals, so a loss in both halves of one diff passes green. (design lock §5.4)
- **`·` U+00B7 is the label separator, and it is the highest-stakes literal in the codebase** — baked into every composed session label, therefore into every zellij tab name via `RenameTab`, and every bar row. Losing it in transit silently yields `x main fix auth`.
- **`✖` is U+2716 HEAVY MULTIPLICATION X, `✗` is U+2717 BALLOT X — different meanings.** U+2716 is `Status::Failed`, a hook-lifecycle status (`clave-types/src/lib.rs:41`). U+2717 is the *stale row* flag, a `bool` not a `Status` (`RowStatus::Stale` in `clave-bar/src/render.rs`, field at `clave-types/src/lib.rs:78`). Both render the same red, so shape is the only discriminator. **A third, unrelated use:** `clave doctor` uses `✗` for a failed check (`doctor.rs:404,415,482`) — a repo-wide replace would corrupt it.
- **[FIXED] The renderer used to build its gutter by string concatenation**, so a dropped or double-width glyph shifted the row's text, and `main.rs` is `test = false` so nothing caught it. `main.rs` now calls `render_rows` (`render.rs`) and holds no visual logic at all. **Keep it that way** — anything you add to `fn render` is untestable by construction.
- **`str::chars()` counts Unicode scalars, not terminal cells** — so an East-Asian wide or combining character miscounts the row. `render.rs` measures with `unicode-width` (held at 0.1 — the line zellij-utils 0.44.3 resolves for its own grid), and it is now **the bar's only clamp**: `main.rs`'s char-counting one is gone. The claim is scoped to the bar — host-side, `hook.rs:109` still does `chars().take(32)` on a composed label, and that one is a *store* budget, not a column budget.
- **A colour blend ported from the ratified preview must round ties to EVEN, not away from zero.** Python's `round()` is round-half-to-even and `f64::round` is not, so a naive port shifts a channel by one and the rendered design silently stops matching the one that was signed off. `Rgb::mix` uses `round_ties_even`; fujiWhite faded 25% onto sumiInk3 puts blue on exactly `149.5`, so this is reachable, not theoretical (`render.rs`, `mix_rounds_ties_to_even`).
- **[DESIGN] Below 27 columns a rendered row is WIDER than the pane, deliberately.** Fixed columns everywhere with `summary` the only flex cell (LEDGER D9) means gutter + title + repo + spaces + margin + caps = 27 cells that never shrink. A row that reflowed its columns to fit would be exactly the failure lock §2.1 forbids, so `render_rows` over-runs instead. Collapsed is now ratified as a width PROFILE (LEDGER D16/D17), so the floor is `Widths::min_intact_cols()` — 27 expanded, 23 collapsed — and the profile is chosen by STATE, which is why a live seek never crosses it. Do not "fix" this by shrinking a fixed column (`render.rs`, `Widths::min_intact_cols`).
- **[SUPERSEDED] `COLLAPSED_TARGET_COLS` is no longer `4`, the width the bar could never reach** — it is **30**, `Widths::COLLAPSED`'s own geometry (LEDGER D17), well above zellij's resize floor. Any collapsed-mode analysis costed against a "text budget 0" row was reasoning about a phantom and does not transfer.
- **[DESIGN] A `glyphs` plugin-config key would reproduce the v0.1.1 double-sidebar** — zellij hashes plugin identity over the whole config map, so a key miss starts a new instance. Glyphs are compiled in; customisation folds into #40. (lock §5.3)
- **[DESIGN] Gutter cells are position-locked and render a space when the glyph is absent; cap columns are reserved blank on unselected rows too.** Otherwise the selected row's content sits one column right of its neighbours — breaking alignment exactly where the eye is most focused. (lock §2.1, §2.2)
- **[DESIGN] A row background must span all 44 columns, including the pad after a short summary** — resetting at end-of-text leaves a ragged selection, which is what the old `SGR 7` over the tab name did. Selection is by recession (25% fade), not by reverse video, and `a_selected_rows_background_spans_every_column` measures it per cell. (lock §6)
- **[DESIGN, now enforced] A live row renders from the STORE, not the zellij tab name** — a tab name is one opaque string with no field structure, so it cannot fill fixed-width columns. `rows()` projects title, summary, repo basename and provenance from the bound `&Agent`; the zellij tab name reaches the bar **only** through `RowContent::Terminal`, i.e. a tab with no agent. Reintroducing `t.name` on an agent row re-opens a second, drifting copy of the label. (lock §7.1)
- **`𖣂` U+168C2 is BAMUM LETTER PHASE-C MBERAE — not a Nerd Font glyph.** A working Nerd Font battery says nothing about its coverage; in practice only Noto Sans Bamum has it. There is no worktree glyph in any surveyed set: zero hits across Nerd Fonts' 10,764 names, 380 octicons, 639 codicons.
- **[DESIGN] The "this terminal renders Plane-15 only" rule was an encoding bug, not a font fact** — the probe's codepoints were lost between writing and running it. A corrected probe rendered every candidate, including U+E0A0. (lock §8.2)

## Process and tooling

- **Bare `zellij` commands from an agent shell mutate the maintainer's OWN session.** Claude Code runs *inside* the user's zellij session — `$ZELLIJ_SESSION_NAME` reflects that, not some sandbox. `zellij attach` variants once injected clave-layout tabs into the live session. **Session lifecycle is the human's; print the command, do not run it.** (docs/dev/TESTING.md)
- **Hot-reload resets plugin state** — a reload reincarnates every bar model from scratch. That is a confound (the state you were watching is gone) *and* a tool (it clears a parity desync and re-hydrates cleanly). Know which one you are relying on.
- **Claude's identity is deliberately NOT sandboxed** — `CLAUDE_CONFIG_DIR` isolation broke auth (ruling 2026-07-18). So scenario seed transcripts land in the real `~/.claude/projects/`, and `~/.claude/settings.json` is one shared hook slot where Claude fires *all* matching hooks — clave keeps exactly one entry per event or they double-fire.
- **`~/.claude` is never yours to write.** Note sandbox task-output paths can *symlink* into `~/.claude/projects/`, so a write believed to be sandboxed can land in the real transcript store.
- **Handoffs and the validation ledger are IMMUTABLE history** — a doc sweep may correct live SOP only, never a dated record of what was run. A blanket "fix every occurrence" instruction once had an implementer falsify a dated quote, inserting a flag that did not exist on that date.
- **A branch updated via `gh pr update-branch` diverges from your local copy** — fetch and merge before pushing. Branch protection requires up-to-date-with-base, so merging PR N forces a branch update on PR N+1 and a fresh CI round. Direct push to `main` is blocked (`enforce_admins: true`); note approvals required is **0**, so "ask before merging" is unenforced.
- **Global git config rewrites HTTPS→SSH** (`url.git@github.com:.pushInsteadOf`), so a dead SSH agent blocks pushes as well as signing.
- **The fugu harness had a silently-passing lane** — its codex lane hardcoded `git diff <base>...HEAD` regardless of `type`, so reviewing UNCOMMITTED work diffed nothing and returned "nothing significant". Fixed in the vendored copy (`.claude/workflows/fugu-review.js:59-74`); a global copy outside this repo may still have it. **A review lane that can only ever agree is worse than no lane.**
- **Workflow `args` must be a real JSON object, not a stringified one** — a stringified value still passes the truthiness check and silently drops the object's fields (`fugu-review.js:55-57`).
- **Subagents are instructed not to write report files** — briefs must ask for the report as the final text response. Subagents also misread per-task constraints as standing project rules; one nearly encoded a session-specific restriction into a project doc.
- **A pre-commit PII blocklist rejects private local path names in staged lines** — genericize to `~/…`, `$TMPDIR/…` before staging, and keep the reason out of commit messages and PR bodies.
- **`~/.claude/projects/` entry names begin with `-`, so a RELATIVE glob over them parses as flags.** From inside the directory, `ls *clave*` expands to `-Users-…` and `ls` reads it as options: `ls: unrecognized option '--var-folders-…'`, exit 1. **The absolute form is fine** — `ls ~/.claude/projects/*clave*` expands to `/Users/…`, which no `ls` mistakes for a flag (measured: exit 0). Getting this backwards is worse than not knowing it, because the absolute form *succeeds* and reads as "there is no trap here". `ls` is also aliased to `eza`, where `-t` means `--time` and errors demanding a field. Canonical command: `find ~/.claude/projects -maxdepth 1 -name '*clave*'`; `/bin/ls --` also works. Cost a round during the #69 spike. (corrected on #81 — the original entry named the wrong failing form)
- **`just install` is retired.** It clobbered stable wasm and CLI from an in-progress working tree. `just sandbox` replaces it and guards three things: it refuses against a live `clave-test`, self-checks that `config.kdl` and `launch.kdl` carry an identical `clave_binary`, and asserts `~/.cargo/bin/clave` and `~/.local/share/clave` were left untouched.
