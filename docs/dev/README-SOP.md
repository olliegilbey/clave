# README SOP

How clave's README is written and checked. The README is the **front door**:
the one document a stranger reads before deciding to try clave. Every change
to README.md is written from these rules and checked against them before the
PR opens.

Exemplar: _commit TBD, set when the v0.2.1 rewrite lands._ When these rules
and the exemplar disagree, the exemplar shows intent; update whichever is
stale and say so in the PR.

## Voice

Ollie's voice: confident, concrete, opinionated. Keep it. Run the `unslop`
skill over new prose. Punctuate with commas, colons and full stops; the
em-dash is retired file-wide.

## The rules

**Truth from source.** Every factual claim traces to the shipped release, the
code, or a command you ran. "What the installer does", "what first launch
does", "what fonts are needed": verify in the source, then write. A claim you
could not verify does not go in.

**Generated, not screenshotted.** Visual assets (the hero frame, the glyph
icons) are rendered by the committed generator from the same source the
product uses: palette imported from `render.rs`, glyphs traced from the real
fonts. Regeneration is one cargo command, recorded in a comment beside the
asset reference. An asset produced by hand goes stale silently; a generated
one cannot drift from the product.

**GitHub is the render target.** Terminal colour and Nerd Font glyphs die in
GitHub code spans: colours drop, glyphs render as boxes. Anything that must be
seen (a coloured dot, a font glyph, a row of the bar) is an image. Judge every
change on the rendered page, not the raw markdown.

**Present tense, zero archaeology.** The README describes what clave is
today. Issue numbers, PR references, version history and design excavation
live in issues, specs and commit messages; the README's only issues link is
the call to action to file one. If a warning needs a why, one sentence of
present-tense why, not the story of how we learned it.

**Keybinds, not commands.** The user drives clave with `Alt` keys; they
almost never type a `clave` subcommand. Describe capabilities ("an agent on
its own branch in its own worktree") and let the keybind table carry the
interface. CLI invocations belong in CONTRIBUTING and the docs, with one
exception: the install story (the installer line, `clave` itself, and
`clave doctor` as its repair pointer).

**KISS install.** The install story is the fewest lines that work (today:
the curl one-liner, then `clave`). Upgrade is two lines. Build-from-source is
a brief fallback subsection holding its own prerequisites. Verification
(checksums, attestations) is one pointer to the release page.

**Tables carry facts, prose carries ideas.** Enumerable things (glyph
meanings, keybinds) sit in tables with a few words per cell. Anything needing
a full sentence sits in short prose beside the table, one paragraph per idea.
When a paragraph starts narrating history or mechanism, cut it against
"present tense" and "keybinds, not commands" above.

## Layout

The ratified skeleton. Reorder only with Ollie's sign-off; trimming within a
section needs none.

1. Title, one-line pitch, the fleet-scale paragraph
2. Hero image (generated frame of the showcase fixture)
3. Vocabulary: one anatomy table, columns in on-screen row order
   (status | battery | mark | chip | repo | description), short prose beneath
   for the smart zone and anything else needing a sentence
4. Try it: runtime requirements, two-line install, two-line upgrade,
   build-from-source fallback
5. Keybind table, plus a short note on the `Ctrl` keys clave frees for
   Claude Code
6. How it works: one-to-two-line bullets, then "What it isn't"
7. Contributing pointer
8. Why "clave", License

## Done means

- Every claim verified against source or a command you ran this cycle
- Assets regenerated by their one command, not edited by hand
- The rendered page checked (GitHub preview or a rendered markdown view):
  no boxes, no monochrome dots, tables lay out
- No issue numbers, no em-dashes, no `clave` subcommands outside the
  install story
- `unslop` pass done on changed prose
