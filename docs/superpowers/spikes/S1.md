# Spike S1 — background repaint (THE ARCHITECTURE GATE)

**Verdict: ✅ PASS** (2026-07-02). The `clave-bar` plugin renders a colored status
glyph for a **non-focused** agent row and updates it live on a `zellij pipe` message
**without stealing focus**. Invariant #11 (the bar renders from clave's pushed model,
decoupled from tab order) holds. **Proceed to S2 (Task 6); do not revisit spec §3.**

## What was observed
Layout `spikes/layouts/s1.kdl`: plugin pane LEFT (unfocused), shell RIGHT (focused).
Driven with `zellij pipe --name clave-status < spikes/s1-msgs/<n>.json`:
- msg 1 (seq=1, working) → left pane showed `● x main working`, **amber** glyph.
- msg 2 (seq=2, needs_you) → glyph turned **red** live, label updated. Focus stayed on the right shell pane.
- msg 3 (seq=1, "STALE…") → **no change** (stayed red) — the monotonic-seq gate discarded the lower seq.
- Re-running msg 1 (seq=1) after msg 2 → **also correctly discarded** (stayed red). Intended: full-replace + monotonic seq means seq ≤ current is always dropped. A second confirmation the seq-gating works, not a bug.

## Plugin-load form
Binary crate (`register_plugin!`, no explicit `fn main`) — loaded and ran fine; **no
cdylib fallback needed** (log: `Loaded plugin '…/clave-bar.wasm' in ~27ms`).

## Render form
**Raw ANSI SGR works.** The glyph rendered as a clean colored `●`, NOT literal escape
bytes. So spec §6.5's `#[fg=…]` markup is NOT required — `println!("\u{1b}[{c}m{glyph}\u{1b}[0m …")`
renders correctly in a Zellij plugin pane. This sets the technique for the real §6.6 bar:
raw ANSI is viable.

## Permission gotcha — IMPORTANT, feeds the setup/packaging plan
A Zellij plugin only receives `zellij pipe` messages once `ReadCliPipes` is **granted**.
Without it, `zellij pipe` times out server-side (`Action CliPipe did not complete within
1s`) and nothing repaints — and the interactive permission prompt was effectively
unusable in a narrow/unfocused plugin pane (never surfaced answerably across several
attempts).
- **Resolution used:** pre-granted by writing
  `~/Library/Caches/org.Zellij-Contributors.Zellij/permissions.kdl`. Format (verified
  from zellij v0.44.3 `zellij-utils/src/kdl/mod.rs`, `PermissionCache::to_string` +
  `from_string`): each plugin is a KDL node keyed by its location string, children are
  `PermissionType` variant names (strum `Display`). Granted `ReadApplicationState`,
  `ChangeApplicationState`, `ReadCliPipes` (the last is what S1 needs;
  `ChangeApplicationState` is pre-granted so S2's `go_to_tab` won't re-prompt).
- **Action item for `clave setup` (§6.5/§6.8 / packaging §7):** the product MUST ensure
  clave-bar's permissions are granted — write/merge a `permissions.kdl` entry at setup,
  or grant on first launch of the clave session. Do NOT rely on the user finding the
  prompt. Fold into the setup subsystem plan.

## `zellij pipe` return behavior (§6.5 follow-up)
`zellij pipe` may not return to the shell prompt immediately (bidirectional pipe that can
wait for plugin output); cosmetic — the repaint happens regardless, `Ctrl-C` returns the
prompt. For the product, confirm `clave hook`'s `zellij pipe` push is fire-and-forget /
doesn't block the hook (add a timeout or background it if needed).

Focus stayed on the right shell pane throughout; the unfocused left plugin pane repainted
