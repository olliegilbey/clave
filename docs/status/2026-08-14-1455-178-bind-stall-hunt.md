## Important Discoveries

- **The retry-budget theory is WRONG, and this is the session's main finding.**
  The prior working hypothesis (carried in #178 and the old handoff) was that
  the bind allowance is spent and never refilled. It cannot explain the field
  report: the allowance is keyed by (row, target tab), and `model.rs:988` gives
  a NEW episode at full budget for a different target — and a different row has
  no entry at all. Each later wake is a different row, so exhaustion cannot
  silence it. Recorded on #178.
- **The live hypothesis is starvation, and it is silent by construction.** A
  `clave-register` broadcast reaches every instance and tells it a row's pane
  id, but pane frames reach only the ACTIVE tab. A background instance can
  therefore know the pane id and be unable to place it in any tab
  (`tab_position_of_pane` returns None) → `joined_here` false → the row is
  cleared, no bind emitted, no budget spent, nothing logged. That is
  `BindStallState::PaneKnownButAbsent`, the state worth the whole exercise.
- **The review defect worth remembering (both reviewers found it independently,
  P2/Major).** `identity_effects()` fails closed TWICE — `!elects_confirmed()`
  and `own_tab() == None` — and both return BEFORE `bind_effects` runs. The
  first implementation reported from inside the bind pass, which made
  `FramesIncoherent` and `OwnPositionUnknown` **unreachable in production**:
  the instrumentation would have been blind to exactly the silences it exists
  to name. Fixed by hoisting the report into the shell.
- **Deviation from the suggested fix, deliberate, accepted:** both reviewers
  proposed moving the evaluation INSIDE `identity_effects` ahead of its gates.
  That changes that function's contract from "the actions to take" to "actions
  plus diagnostics" and **broke five unrelated tests** that assert emptiness to
  mean nothing-happened (`birth_touch_is_deferred_...`,
  `identity_effects_emit_nothing_from_an_incoherent_frame_...`,
  `tab_close_prunes_stale_ids_...`, and two proptests). Taking the report
  separately in `settle_identity` preserves the contract and moves no unrelated
  test. If a future reviewer re-raises this, that is the answer.
- **`own_tab` on the effect is `Option<usize>` on purpose** — not knowing our
  own tab is one of the reported states, so it cannot be a precondition for
  reporting. `main.rs` renders `None` as "unresolved tab".
- **This session is sandboxed to its worktree.** `git -C <other checkout>`,
  `cd ~/code/clave && git …`, and compound commands the guard cannot verify are
  all REFUSED — including when Ollie types them with the `!` prefix, because
  that routes through this session's shell. Anything touching the primary
  checkout must be run by him in a separate terminal.
- **Stale drafts in the primary checkout blocked his pull** (resolved). The
