## Important Discoveries

**The migration gap — the one live question, found twice independently.**

`live_session` is **null on all 18 rows of Ollie's real store** (verified by
reading `~/.local/state/clave/agents.json` read-only). It has to be: they were
written by a binary that had no such field. So at the first resurrection after
the cut, every row falls back to the minted uuid — pre-#99 behaviour, one last
time. For any row `/clear`ed since its last resurrection, that reopens the
pre-clear conversation, and the hooks then report *that* id and preserve `None`,
stranding what was live. Codex flagged the same thing on `main.rs:249` (P1).

**Do NOT "fix" this by guessing.** Backfilling by picking the newest transcript
in the project dir is precisely the heuristic #99 avoided, and attaching the
WRONG conversation is worse than being one behind. Nothing is destroyed either
way — a stranded conversation is still reachable via `claude --resume <id>` from
its directory, just not through clave.

**The mitigation is procedural and its outcome is UNKNOWN.** After `just release`
rewrites the hooks in `~/.claude/settings.json` to the new binary, prompting a
live agent once should make the new hook write `live_session` for that row —
*if* a running Claude re-reads `settings.json` per event rather than caching it
at session start. Nobody has measured this. It is a cheap experiment with a
definitive answer and belongs in FOOTGUNS either way.

**A mistake I made, so it is not repeated:** I asserted in issue #102 and in a PR
reply that "it is unverified whether Claude relocates a transcript on a cwd
change". It was already settled at `FOOTGUNS.md:124`, measured in #59, counted
131 times in #79. I failed to grep the file this repo exists to make people grep.
Both places are now corrected. **Grep FOOTGUNS before claiming anything is
unknown.**

**A second over-read, caught within one message:** I counted "13 of 18 rows have
a newer transcript beside them" and called it rotation. Project dirs hold
transcripts from every `claude` ever run there, including the agent doing the
counting. The honest statement is the `live_session`-is-null one above.
