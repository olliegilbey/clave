## What's Working

- The model is the safety net. Every decision is in `model.rs` behind tests that fail when the logic flips: `paints` returning `wants` unconditionally, dropping `!hidden`, or `spend_fast_tick` always true would each turn a new test red.
- The paint gate is closed by construction. Every event and pipe answer passes through `paints`, and the text test pins it. A new event arm cannot bypass it, because early returns live inside `handle_event`.
- The hidden-bar fix deliberately keeps parse, apply and identity effects. It drops only the paint. Do NOT widen it to defer parsing unless you add a bind-safe trigger. A hidden bar must still bind agents that start in its tab while Ollie walks on (that is exactly the restart flow).
- Identical frames still run `apply_tabs`/`apply_panes`, because the #162 re-anchor retries on the next frame. Only the paint is skipped. `acted` (effects non-empty) still paints, which covers MarkRead's local unread clear.
- The width machine needs no off-screen paint. It is focus-gated, and it settles on the paint after the tab returns (`model.rs` `width_effects` doc, "The focus gate").

## Important Discoveries

- **Spinner speed-up mechanism.** After a stall past `FAST_TICK_STRAND_SECS` (2 whole seconds), `arm_fast_tick` stops believing its claim and the next paint starts a second timer. The first timer was late, not lost, so both chains re-arm forever and each one advances `anim_frame`, which doubles the speed. The chains die only when the spinner stops (tab switch or turn end). The fix drops a fast expiry that lands within 150 ms of the last spent one, and leaves the claim alone. The window must be over 100 ms: at exactly half a period apart, both chains would otherwise live. The test sweeps every offset from 0 to 199 ms.
- **First timer-test draft used 100 ms.** It failed in reasoning at offset = 100, before it ever ran. That is why the window is 150.
- **Bar spinner glyphs are Claude Code's own flower** (`card.rs` `THINK_FRAMES`). If Ollie's "fast flower" is the one inside Claude's pane, it is not ours. He has not said which one he means.
- **Restart-storm data from the live log.** Each instance received ~2 beacons/s, and values rotated 1, 6, 11, 10, 9, 2 at ~0.5 s intervals. There were 13 `KeybindPipe did not complete within 1s` errors. Each of those freezes that client's router for a second (`route.rs` `wait_for_action_completion`; the router thread is per client, `lib.rs:968`), and that freeze was the "violent lag". Beacons stopped at 09:26, when navigation stopped.
- **`zellij delete-session` after `kill-session` prints "not found".** That is harmless.
