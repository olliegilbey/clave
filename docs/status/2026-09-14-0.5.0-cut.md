## The sequence, in the main checkout

Local only — nothing reaches the remote:

```bash
git merge --ff-only chore/release-0.5.0   # crosses 6198311 and the bump
git tag v0.5.0                            # lightweight, as v0.4.0 was
just release
```

`clave release` refuses a dirty tree or an untagged HEAD, so a failure
there is the gate working. A running session keeps the files baked at its
launch; the cut lands at the next cold start.

**Rolling one more PR in later** means merging it, moving the tag, and
re-running `just release`. The bump commit itself does not change. When the
cut is final, the bump reaches `origin/main` the way every other commit
does — a PR — and the tag is pushed after the go.

## Rollback

Every previous version is still installed under
`~/.local/share/clave/bin/`, so a bad cut is a re-run of `just release` at
an older tag, not a rebuild.
