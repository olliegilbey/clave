## Important Discoveries

- **Design B (pure-KDL swap_floating_layout) is DEAD — measured, not
  suspected.** The layout clamp path (`position_floating_pane_layout`)
  resolves `x "0%"` from ABSOLUTE column 0 (pane covers the bar) and caps
  x+width at the bar-reduced `viewport.cols`, so flush-right-of-a-54-col-bar
  at ≥80% width has NO expressible coordinates. Recorded in FOOTGUNS 74
  (updated in this diff) and in `swap_layouts_kdl`'s comment. Never re-try.
- Only the COORDINATES path (`adjust_coordinates`) floors x at viewport.x —
  reached via Run binds, CLI `new-pane --floating -x…`, and plugin
  `open_terminal_floating`. This is why the fix is plugin-routed.
- zellij-tile 0.44.3 HAS `show_floating_panes(tab_id)` /
  `hide_floating_panes(tab_id)` (shim.rs:2828/2851) — per-tab, blocking,
  return state-changed; the SAME tab fns ToggleFloatingPanes uses, NOT the
  suppress path. Issue #207's "no toggle shim" claim is wrong.
- **THE REGRESSION (debugged, root-caused, unfixed): a bare-URL
  `start-or-reload-plugin` SPAWNED A SECOND CLAVE BAR as a real tiled pane.**
  Ollie flagged it from his screen: two bars, "this should not be possible."
  Mechanism, verified in zellij v0.44.3 source: `reload_plugin` matches
  instances by location AND CONFIGURATION
  (`wasm_bridge.rs:692-693`); the drive's ct.sh call passed the bare
  `file:` URL = EMPTY config, the real bars carry `clave_binary "clave"`,
  so the match found nothing → `PluginDoesNotExist` → "starting it instead"
  (`plugins/mod.rs:429-470`) → `AddPlugin` opens a visible TILED pane in the
  active tab (`screen.rs:7922-7938`, `should_float=Some(false)`). Corollaries:
  the ORIGINAL bar never reloaded (only one `shell-arm-1` loaded line — the
  new pane's); the new pane is non-selectable full-height right-flush, so
  offset_viewport halved the floating viewport (width 66 = 97%·68, correct
  math over polluted state); the spawn evidence came from the NEW instance,
  which legitimately self-elected via the birth beacon in the active tab.
  This is FOOTGUNS 61's config-is-identity rule biting through the reload
  path. Clave's own surfaces (#44, env-uuid binding) were never the hole —
  an agent driving zellij's CLI with a mismatched identity was.
- A payload-less CLI pipe is shape-identical to zellij's #45 blank twin and
  is dropped; scripted drives must send `-- <payload>`, hence the dual arms.
- `OpenTerminalFloating` needs `PermissionType::OpenTerminalsOrPlugins`
  (zellij_exports check_command_permission); show/hide ride the already-held
  ChangeApplicationState.
- Ollie watched the drive live and confirmed the x=54 placement ("I like the
  idea of it"). Two separate two-of-something sightings, don't conflate:
  the two FLOATING panes mid-probe were my deliberate side-by-side geometry
  comparison (fine); the two BARS afterwards were the regression above (not
  fine).
