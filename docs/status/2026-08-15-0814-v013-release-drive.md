## Important Discoveries

### Zellij swap layouts — settled from `zellij-server` 0.44.3 source

Not vendored; fetched from crates.io and read. Installed zellij is Homebrew
0.44.3, so versions match.

- **A swap re-uses the running plugin pane; it never spawns a second copy.**
  `tab/mod.rs:1093-1141`, `tab/layout_applier.rs:160-234`, matching rule at
  `:1218-1250`. **Condition:** both arrangements must declare the plugin
  identically — only size may differ, because identity is location plus
  configuration. There is a test pinning this.
- **A swap applies to the FOCUSED tab, not the requesting one.** The plugin's
  request carries its pane identity and the routing layer discards it:
  `plugins/zellij_exports.rs:119-138` and `:3117-3128`, dropped at
  `route.rs:1255-1270`, resolved against the client's active tab at
  `screen.rs:7547-7573`. No tab-scoped form exists for plugins — only as a
  command-line action. **Fixed by gating: switch only when your own tab is
  focused, otherwise hold the desired end state and settle on regaining focus.**
- **Still unverifiable from source:** whether the first switch on a tab lands on
  the *opposite* layout. The declaration order depends on it. If it is backwards,
  the first collapse of every session does nothing and produces no repaint to
  notice. **This needs the live drive.**

### A simplification deliberately NOT built

Zellij reports which of the two layouts a tab is in, **by name**, synchronously —
`active_swap_layout_name` on tab info the sidebar already reads. The branch
instead keeps a one-render "did the pane move the way I wanted" check, which is
the last surviving piece of the watch-your-own-repaints pattern the redesign
exists to delete. **Not a dead end — worth doing, deliberately deferred** to
avoid scope creep on a branch under review. Good first follow-up after the tag.

### Signing and pushing when Ollie is away

- His 1Password signer auto-locks. A plain `git commit` then fails with
  `fatal: failed to write commit object` and **prints the fix**.
- The sanctioned path: let the plain attempt fail, then **re-run the same
  command** prefixed `GIT_AUTHOR_NAME=Claude GIT_AUTHOR_EMAIL=noreply@anthropic.com
  GIT_COMMITTER_NAME=Claude GIT_COMMITTER_EMAIL=noreply@anthropic.com`. The
  failed attempt first appears to be required. Say in your reply that the commit
  is Claude-signed.
- His **global pre-push hook refuses unsigned commits** and its header says it
  exists to stop agents routing around signing failures. **Respect it
  absolutely.** If a push is refused, stop and report — do not amend, do not
  bypass, do not seek another route.
- `main` does NOT require signed commits, so Claude-signed commits merge fine.
- This session is worktree-isolated: `git -C`, compound commands the guard
  cannot verify, and token-bearing push URLs are all REFUSED here. Subagents in
  their own worktrees can do what this session cannot.
